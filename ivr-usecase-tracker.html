Calling from inside the app — in-app Call CTA, seamless bridge

UC 01 CSP user taps Call CTA in the CSP App (registered SIM)
Path 1 ✓ Live

A CSP user opens a ticket in the CSP App and taps the Call CTA to reach the customer. The dialer opens with the Wiom IVR Masked number pre-filled. The user dials, and the call is bridged seamlessly — no PIN prompt, no waiting. The customer's phone shows the Wiom IVR Masked number, never the CSP user's personal mobile.

How it works — business flow

What the user does and sees

  1. CSP user opens a Restore / Install / Pickup ticket card in the CSP App.
  2. Taps the Call CTA.
  3. Phone dialer opens with the Wiom IVR Masked number pre-filled.
  4. Taps dial.
  5. Customer's phone shows the call coming from the Wiom IVR Masked number — not from the CSP user's personal mobile.

Scenarios — and how each is handled

✓ Handled Customer picks up
Both parties talk. The call ends naturally. The call disposition and the recording are saved on the IVR backend.
✓ Handled Customer doesn't pick up
CSP user hears: The customer then receives a push notification on the Customer App:
आपने हमारे टीम का कॉल मिस कर दिया है। कृपया उनसे बात करने के लिए वापस कॉल करें।
When the customer dials back, the flow continues as UC 09 (if they have one active ticket) or UC 10 (multi-ticket).
✓ Handled CSP delays dialling — short-lived in-call mapping expires
If the CSP user opens the dialer but doesn't tap dial within the short TTL window, the seamless-bridge mapping expires. When they eventually do dial, the call falls through to Path 2 and bridges via the identification chain (which still recognises the CSP from sim_inventory). Continues as UC 03 or UC 04. No user-visible failure.
✓ Handled CSP cancels / ends the call themselves before customer picks up
Call doesn't connect. No IVR audio plays — call never reaches the IVR backend. Behaves like any standard outbound call cancel from the phone dialer.

UC 04 CSP dials back from call log — multiple active tickets
Path 3 ✓ Live

A CSP user has 2+ open tickets and wants to call one of those customers back. They tap the saved Wiom IVR Masked number in their call log. The IVR recognises them but can't tell which customer they want — so it asks for the 6-digit PIN. The CSP reads the PIN from the relevant ticket card in the CSP App (or the SMS), enters it, and the bridge fires.

How it works — business flow

What the user does and sees

  1. CSP user taps the saved Wiom IVR Masked number in their call log.
  2. "Please enter your PIN" voice prompt.
  3. Looks up the ticket in the CSP App (or the SMS) to find the 6-digit PIN.
  4. Enters the PIN on the dialer keypad.
  5. Customer's phone rings showing the Wiom IVR Masked number.

Scenarios — and how each is handled

✓ HandledCorrect PIN → customer picks up
Bridge fires to the right customer for that ticket. Both parties talk. Recording saved.
✓ HandledCorrect PIN → customer doesn't pick up
CSP user hears: Customer gets a missed-call alert on the Customer App.
✓ HandledWrong PIN (1st attempt)
CSP user hears: IVR asks for the PIN one more time. The CSP gets a second chance to enter the correct PIN.
✓ HandledWrong PIN twice
CSP user hears: Call ends. The CSP has to redial and start over.
✓ HandledNo PIN entered (timeout)
If the caller doesn't enter anything within the timeout, they hear: IVR re-prompts up to three times. After three timeouts, the call ends.

Edge cases — No active ticket on the IVR Masked number — dead-end with redirect

When a customer or CSP dials the IVR Masked number but the IVR finds no active ticket against their mobile (e.g. ticket already closed), the IVR plays a dedicated message that politely tells them where to call instead — the Wiom Call Center for customers, the Trustline 7836811111 for CSPs — and ends the call. No bridge is attempted.

Issue Type: {{ Event.ticket_type }}

- Wiom
English: "You have received a ticket. If you call from a number other than your registered number, talk by entering csp_pin in the IVR. Issue Type: ticket_type. Ticket ID: execution_candidate_id".

Variables: csp_pin = the CSP-side 6-digit PIN · ticket_type = Install / Restore / Pickup · execution_candidate_id = the unique ticket identifier.
Carries the PIN used in these use cases:
  • UC 04 · UC 06 — CSP dials back, multi-ticket (forwardable PIN source as alternative to the in-app card)
  • UC 12 — CSP from unregistered SIM (load-bearing if the CSP App isn't reachable)
  • UC 13 — Colleague forwarding (the SMS is what gets forwarded)
